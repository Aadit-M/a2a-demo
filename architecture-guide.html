A SHORT GUIDE TO THE ARCHITECTURE

One system doesn’t
have to do it all.

Keep each team’s agent and tools in its own service. Use A2A to request work across boundaries, and return only the information the other team needs.

THE IDEAS BEHIND THE DEMO

Why separate agents can help

These are architectural options and trade-offs, not security guarantees supplied by a protocol.

01 DATA BOUNDARIES

Keep team data in its own boundary

A shared LangGraph can make shared state and orchestration convenient, but that also means the orchestrator may handle information from multiple steps. Separate agent services create a clearer place to enforce departmental access boundaries.

IN THIS KYC FLOW

In this demo, FinCrime returns a risk result rather than sending its raw screening notes to the onboarding workflow.

IMPORTANT

A2A does not automatically create zero trust or encrypt messages. Service isolation, least-privilege access, authenticated connections, and careful payload design still matter.

02 INTEROPERABILITY

Let teams choose their agent stack

LangGraph is useful inside an agent service. A2A gives independently operated agents a common way to describe and exchange work, so departments do not have to share one orchestration graph or framework.

IN THIS KYC FLOW

The onboarding team can keep its own workflow while a separate FinCrime service accepts a review task and returns a result.

IMPORTANT

A standard makes integration easier, not automatic: teams still need compatible capabilities, message formats, versions, and operational agreements.

03 IDENTITY & AUDIT

Make handoffs easier to verify

A task ID and a clearly scoped result make it easier to follow who handled a review. Agent descriptions and signed results can add useful evidence when connected to real identity and key-management systems.

IN THIS KYC FLOW

The final KYC step asks a separate QA service to verify the FinCrime result before marking its review complete.

IMPORTANT

A2A does not automatically authenticate every agent or sign every artifact. This demo uses a shared-secret HMAC for illustration; production needs protected keys, trusted identity, authorization, and independent verification.
